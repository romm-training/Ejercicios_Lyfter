**1. SELECT**

El comando `SELECT` es utilizado para seleccionar datos de una o varias tablas, incluso, de una o varias bases de datos, si la tecnología lo permite. Es uno de los comandos más importantes ya que permite recuperar datos para que sean mostrados en pantallas, reportes, comprobantes, mecanismos de autenticación, entre otros.

Permite recuperar todas las columnas mediante el `*` o un grupo de columnas. Por cierto, el comando `SELECT *` no es recomendado ejecutarlo en ambientes productivos, especialmente en tablas con muchos registros. Lo correcto es indicar las columnas que se requieren retornar.

Dependiendo de la base de datos, permite hacer operaciones matemáticas, asignaciones de variables, y, hasta generar otros queries a partir de datos existentes.

El comando `SELECT` es **mandatorio** para realizar cualquier consulta.

**2. ORDER BY**

Permite order el resultado de una consulta por una o varias columnas. Su uso no es mandatorio, o sea, si no se incluye el `ORDER BY` en una consulta, la consulta igual funciona, solo que será ordenada usando los criterios que use la base de datos, por ejemplo, las llaves primarias e índices existentes.

Se puede realizar un ordenamiento ascendende o descendente usando los comandos `ASC` y `DESC` respectivamente.

Se debe tener especial cuidado al usar el `ORDER BY` ya que un ordenamiento mal definido, sobre todo en tablas con gran cantidad de registros, puede afectar el rendimiento de toda la base de datos, e incluso del servidor al consumir los recursos (memoria, CPU y disco duro) del mismo.

Es importante que las columnas utilizadas en el `ORDER BY` estén **indexadas**, para que la base de datos pueda organizarlos con mayor eficiencia. También, se recomienda en la medida de lo posible, no ordenar por columnas tipo string con tamaño muy largo.

**3. LIMIT**

Limita la cantidad de registros retornados en una consulta. Es muy importante en funcionalidades de paginación junto con `OFFSET` y para realizar consultas sin afectar el rendimiento de la base de datos. Por ejemplo, no es el mismo consumo de recursos hacer una consulta que retorne 500000 registros que retornar solo 50.

En algunos motores se utiliza `TOP` en lugar de `LIMIT`, pero la función es la misma.

Su uso es **opcional**.

**4. GROUP BY**

Su función es agrupar las filas por una o más columnas. Es especialmente últil en consultas que realicen cálculos matemáticos, aritméticos y estadísticos.

Al igual que con el ordenamiento, se debe tener cuidado con las columnas que se elijen para agrupar ya que, si no están **indexadas**, puede provocar problemas de rendimiento en la base de datos.

Su uso es **opcional**.

**5. INNER JOIN**

Es un comando que permite seleccionar registros de dos tablas siempre que la columna utilizada para establecer la relación tenga los mismos valores en ambas tablas. Por ejemplo, si se tiene la tabla **Customer** y la tabla **Invoice**, se puede seleccionar datos de ambas tablas siempre que el valor de llave primaria de la tabla **Customer** exista en al menos un registro de la tabla **Invoice**.

SELECT c.id, c.name, i.number, i.date
FROM Customer c 
    INNER JOIN Invoice i 
        ON c.id = i.customerId;

La consulta va a retornar el id y nombre del cliente, así como el número y fecha de factura de todos los registros de cliente cuyo id exista en el customerId de la tabla factura. Esta relación se establece con el comando `ON`. Si hay clientes que no tienen facturas, no serán seleccionados.

Este comando es muy utilizado para aprovechar la normalización, ya que permite obtener columnas de tablas por medio de las llaves primarias y foráneas existentes.

**6. LEFT OUTER JOIN**

Permite seleccionar los registros de la tabla de la izquierda aunque no haya registros en la tabla derecha.

SELECT c.id, c.name, i.number, i.date
FROM Customer c 
    LEFT JOIN Invoice i 
        ON c.id = i.customerId;

En esta consulta, se van a seleccionar todos los clientes, tengan o no tengan facturas. Cuando no hay facturas, los campos número y fecha se retornan con valor `NULL`.

**7. RIGHT OUTER JOIN**

Permite seleccionar los registros de la tabla de la derecha aunque no haya registros en la tabla izquierda.

SELECT c.id, c.name, i.number, i.date
FROM Customer c 
    RIGHT JOIN Invoice i 
        ON c.id = i.customerId;

En esta consulta, se van a seleccionar todas las facturas, tengan o no tengan clientes. Cuando no hay clientes, los campos id y nombre se retornan con valor `NULL`.

### Buenas Prácticas

| Comando | Buenas prácticas |
| --- | --- |
| **SELECT** | 1. Evitar `SELECT *` en producción; en lugar, seleccionar las columnas necesarias. <BR> 2. Usar alias (`AS`) para dar nombres claros a columnas. <BR> 3. Documentar consultas complejas con comentarios para facilitar mantenimiento. |
| **ORDER BY** | 1. Especificar siempre `ASC` o `DESC` según se requiera, para evitar que la base de datos ordene según su criterio. <BR> 2. Usar columnas indexadas para ordenar con el fin de mejorar el rendimiento de la consulta. <BR> 3. Si se ordena por múltiples columnas, definir el orden explícito de cada una. |
| **LIMIT** | 1. Usarlo junto con `ORDER BY` para obtener resultados consistentes (ej. “top 10”). <BR> 2. En paginación, combinar `LIMIT` con `OFFSET` para navegar resultados. <BR> 3. No depender de `LIMIT` para lógica de negocio crítica ya que es sólo un límite a la cantidad de filas retornadas. |
| **GROUP BY** | 1. Asegurar que todas las columnas en el `SELECT` que no son agregadas (sum, avg, count) estén en el `GROUP BY`. <BR> 2. Usar funciones de agregación (`COUNT`, `SUM`, `AVG`) de forma clara. <BR> 3. Considerar índices en las columnas agrupadas para mejorar rendimiento. |
| **INNER JOIN** | 1. Definir siempre la condición de unión (`ON`) para evitar producto cartesiano. <BR> 2. Usar alias de tabla para mayor legibilidad. <BR> 3. Verificar duplicados: un mal `JOIN` puede multiplicar filas inesperadamente. |
| **LEFT JOIN** | 1. Usarlo cuando se requiera conservar todos los registros de la tabla izquierda. <BR> 2. Manejar valores `NULL` en columnas de la tabla derecha. <BR> 3. Documentar el propósito: muchas veces se usa para detectar “faltantes”. |
| **RIGHT JOIN** | 1. Usarlo solo si realmente necesitas todos los registros de la tabla derecha (en muchos casos un `LEFT JOIN` invertido es más claro). <BR> 2. Manejar valores `NULL` en columnas de la tabla izquierda. <BR> 3. Revisar si el motor SQL soporta bien `RIGHT JOIN` (algunos lo reemplazan por `LEFT JOIN`). |
